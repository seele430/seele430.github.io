Unimere · Personal workspace

Many flows. One clear space.

Unimere is a personal workspace I am building. The web app covers chat, reminders, jobs, and artifacts. An official QQ bot sends requests to my machine and returns images, documents, or HTML results. The interface uses React, with FastAPI and SQLite on the backend.

Platform console

The console tracks queues, nodes, sandboxes, and executions. Request acceptance, terminal states, and capacity changes are counted separately, so a 202 response is not mistaken for a successful run.

202 means accepted; hold does not mean scaled; available capacity is calculated from valid leases.
03

QQ remote channel

Send a request in QQ and the local service returns the result. These screenshots are from actual runs.

Early versions used NapCat with a secondary account, whose login session often expired. The current version uses an official QQ Open Platform bot over an outbound persistent connection, so no public IP address is needed.

Posters retain their sources and verification status. Figures that were not checked online are marked separately.

05

Implementation notes

A few implementation details related to reliability.

  • Multi-agent handoffsLeases, fencing, and idempotent steps coordinate handoffs. Runs can resume or continue after interruption without two processes writing the same step.
  • Test runnerSQLite and socket guards sit outside the tests. A test fails if it touches the real database or the network.
  • Metric definitionsThe meanings of 202, hold, and available capacity are defined in code and comments, with the frontend and backend using the same rules.
  • Artifact recordsArtifacts include SHA-256 hashes and previews, with diffs between two versions. Deletion requires a dry run followed by confirmation.
